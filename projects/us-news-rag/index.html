미국 주식 뉴스에 물어보는 챗봇, 그리고 답의 품질을 지켜보는 기록.

2026.02 · 약 1주 개발 2026 개인 프로젝트
소스 저장소 ↗

왜 만들었나

미국 주식을 하다 보면 뉴스 읽는 시간이 점점 늘어난다. 다 읽을 수는 없으니 물어보고 싶어진다 — '오늘 엔비디아 소식 뭐 있어?' 그런데 그냥 챗봇에게 물으면 그럴듯하게 지어낸 대답이 나온다. 근거가 되는 뉴스에서 답을 찾고, 그 답이 괜찮은지 매번 채점하고 싶었다.

핵심 기능

  • 뉴스를 모은다 — 여러 출처에서 미국 주식 뉴스를 긁어와 정리하고 중복을 없앤다.
  • 두 방식으로 찾아 섞는다 — 뜻이 비슷한 것과 정확히 같은 단어, 둘 다 잡도록 검색을 섞고 다시 줄을 세운다.
  • 질문을 바꿔서 — 종목명을 회사 이름으로 바꾸고, 가상의 질문을 만들어 더 잘 찾게 하고, 최근 뉴스를 우선한다.
  • 스스로 다시 찾는다 — 찾은 자료가 부족하다고 판단하면 다시 검색하거나 그 자리에서 뉴스를 더 긁어온다.
  • 답은 흐르는 대로 — 답변이 만들어지는 대로 보여준다.
  • 모든 대화에 점수를 — 관련성·정확성·완결성을 자동으로 채점하고 비용과 시간도 함께 남긴다.
  • 세 개의 화면 — 채팅, 뉴스 관리, 품질 그래프를 보는 대시보드.

주요 기술 성과

  • LangGraph 기반 Self-RAG / CRAG 상태 머신 — 단발성 검색에 의존하지 않고, 검색 결과의 관련성을 스스로 평가해 웹 크롤링으로 보충하거나 재시도하는 복합 파이프라인 구축.
  • BM25 + ChromaDB 하이브리드 검색 & FlashRank 리랭킹 — 희소 키워드(BM25)와 밀집 벡터(ChromaDB)를 RRF로 융합 후 재순위화하여 정보 검색 정확도 최적화.
  • Langfuse LLM-as-Judge 품질/비용 트래킹 파이프라인 — 프롬프트 버전 및 검색 모듈 변경 시 대화별 관련성·정확성·완결성 점수와 토큰 비용을 정량적으로 추적·기록.

설계 이야기

찾아서 붙여 넣는 단순한 RAG로 시작했는데 부족한 순간이 자주 보였다. 질문을 다시 쓰고, 검색을 섞고, 결과를 스스로 판정해 다시 찾는 흐름을 하나의 그래프로 엮었다. 어떤 실험을 했는지, 프롬프트를 바꾸면 점수가 어떻게 움직이는지 전부 기록으로 남겨서 나중에 돌아볼 수 있게 했다. 처음부터 끝까지 실행된 노트북이 이 파이프라인이 실제로 돌아갔다는 증거다.

어떻게 만들어 갔나

노트북에서 시작했다. 뉴스를 모으고, 찾고, 답하는 각 단계를 직접 돌려보며 어디서 삐걱대는지 봤다. 답이 부족할 때마다 기법을 하나씩 얹었고, 구조가 정리되면 코드로 옮겼다. 노트북은 버리지 않고 기록으로 남겼다.

만든 방식

AI 도구로 프로토타입은 빠르게 만들되, 다음 단계로 넘어가도 되는지 판단은 내가 했다. 기록 없는 실험은 하지 않았고, 데이터와 평가 결과는 로컬에만 뒀다. 개인 실험으로 시작해 여기까지 확인했다 — 그게 이 프로젝트의 정직한 상태다.
