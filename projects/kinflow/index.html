KinFlow

집안일을 정확하게 나누는 앱.

2026.07 시작 · 약 3주 진행 내부 alpha · 평가용 Android 우선
소스 저장소 ↗

왜 만들었나

집안일 앱은 많은데 둘이 사는 집에는 다들 안 맞았다. 부모-자녀용 가족 앱이거나, 팀 프로젝트용 툴이거나. 필요한 건 단순했다 — 이번 주 설거지를 서로 바꾸고 싶을 때 '이번 주만' 바꾸고 다음 주부터는 원래대로. 이런 게 어이없게도 제일 어려운 문제이고, KinFlow는 거기서부터 만들었다.

핵심 기능

  • 오늘 할 일과 일정을 한 화면에서 만들고 끝낸다.
  • 반복 집안일의 예외 — 이번 주만 바꾸기, 전체 바꾸기, 이번 주부터 바꾸기를 구분하고, 취소했던 것도 경계를 지켜 복구한다.
  • 둘 사이의 신뢰 — 초대는 한 번 쓰면 끝나고, 역할 바꾸기나 나가기 같은 민감한 일은 기록이 남는다.
  • 끝내면 바로 알림 — 상대방이 무엇을 끝냈는지 다 물어보지 않아도 된다.
  • 한국어·영어 — 큰 글씨, 화면 낭독, 넓은 화면까지 기본으로 지원한다.

주요 기술 성과

  • Supabase RLS(행 수준 보안) 기반 데이터 격리 — 공격 시나리오(가구 간 데이터 침범, 권한 우회)를 방어하는 가구 단위 행 수준 보안 정책 수립.
  • 서버 주도 반복 일정 상태 모델 — 회차 경계, 예외 처리, 되돌림 연산을 서버(PostgreSQL)에서 단일 진실 원천(SSOT)으로 관리해 클라이언트 변조 방지.
  • 포트/어댑터(Clean Architecture) 아키텍처 — 도메인·데이터·프레젠테이션 계층 분리 및 저장소 추상화로 화면 확장에 강한 구조 설계.

설계 이야기

'이번 주만 바꾸기'가 제일 위험한 기능이라서, SSOT는 앱이 아니라 서버가 갖기로 했다. 두 사람이 각자 폰에서 같은 집안일을 고쳐도 서버가 순서를 정해주면 안 꼬인다. 두 집의 데이터가 섞이면 안 되는 일이라 데이터 자체가 집 단위로 격리되게 만들었고, 알림처럼 무거운 일은 서버가 뒤에서 천천히 처리한다.

어떻게 만들어 갔나

서버의 반복 규칙을 먼저 문서로 정리하면서 시작했다. 개발 내내 되물은 질문은 '이건 서버가 정해야 하나, 앱이 정해야 하나?'였다. 회차의 경계와 기록은 서버로 올리고 화면 상태는 앱에 두는 선을 계속 그었다. 두 사람이 실제 폰 두 대로 써보는 마지막 관문은 아직 통과 전이고, 그대로 적어뒀다.

만든 방식

문서, 계약, 구현, 증거 순서로만 진행했다. AI 도구가 구현을 빠르게 만들어줬지만 가구를 어떻게 모델링할지는 내가 정했고, '다른 집 사람이 정말 못 보는지'를 확인하는 테스트는 공격자가 된 기분으로 직접 추가했다. 지금은 내부 평가용 alpha다.
